# The program protocol's frame profile: the frames of a program's channel
# (docs/design-programs.md#the-startup-message,
# docs/design-programs.md#the-program-protocol) and their bounds
# (docs/design-abi.md#program-protocol). tools/lib/erx/abi_emit_protocol.rb
# generates the Erlang grammar build/gen/otp/erts/preloaded/src/erx_prog_grammar.erl
# from it, and tools/lib/erx/abi_emit_profile.rb the table liberx's C check
# reads (build/gen/include/erx/prog_profile.h and
# build/gen/liberx/generated/prog_profile.c).
#
# Readings where the programs and pipes designs state no bound:
# * A pid and a pgid are 2 to 2^31 - 1 and a ppid 1 to 2^31 - 1, as the
#   startup message gives them.
# * A pipe's number, an end's number, a write end's number and a pipe's
#   count of write ends, pos_integer() in the designs, are u32 from 1, as the
#   pipe server's C layouts hold them (docs/design-pipes.md#the-pipe-servers-records);
#   a read end's index is 0 to pipe_rix_max, and a write end's list of
#   read ends holds at most pipe_readers_max of them and a read end's,
#   the others, at most pipe_rix_max.
# * A read end's list of write ends holds at most pipes_quota entries: each
#   is a lane of its session's pipes, which the pipe server holds to that
#   quota (docs/design-pipes.md, Limits).
# * The data area's Slots, its count of 64 KiB slots, is 1 to 16, the
#   slots a request may name.
# * An open is any u16, an entry of the program's open table.
# * A mem descriptor's range is in pages of erx_abi.txt's page_size, a first
#   page from 1 and a count from 1, each a u32, which the startup message's
#   C layout holds: the mapping starts below 2^44 bytes and ends below 2^45,
#   and page 0 is never mapped.
# * A file request's path is any text without a NUL a program's open
#   names, relative or absolute, up to prog_path_max bytes. It is not held
#   to UTF-8 here: the handler resolves it through the program's namespace
#   (erx_path), which answers a name that is not UTF-8 with einval
#   (docs/design-files.md, "Resolving a path"), as a POSIX call fails.
# * A file request's flags are 9P2000.L's open flags as a u32, the bits
#   the handler maps (p9_o_* of protocols/9p.txt); a file mode is 0 to
#   8#7777.
# * A read or a write names a data area slot, 0 to prog_data_slots_max - 1,
#   which the handler checks against the program's own slots, and a count of
#   1 to prog_data_slot_bytes, one slot's bytes (liberx answers a count of 0
#   itself and sends a larger one in parts). Its reply's count is 0 to the
#   same, 0 at the end of the file; that it is at most the request's own
#   count no grammar can state, so the handler holds a reply to it and
#   liberx copies no more than it asked for (docs/design-programs.md,
#   "Reads and writes").
# * A pread's or a pwrite's offset is 0 to 2^63 - 1, FreeBSD's off_t: liberx
#   answers a negative one with EINVAL itself, as FreeBSD's kern_preadv
#   does. A seek's offset is any off_t, relative to its whence, bof, cur or
#   eof (SEEK_SET, SEEK_CUR, SEEK_END, which liberx alone maps), and its
#   reply's the offset reached, 0 to 2^63 - 1 (docs/design-programs.md,
#   "Open-file descriptions").
# * A getattr's attributes are FreeBSD's struct stat fields that a file's
#   server gives, each a key of stat only when it gave it: a mode as
#   mode_t's 16 bits, an nlink, a uid and a gid as u32, a size as an
#   off_t, and each time as a time_t of whole seconds with its nanoseconds
#   apart, 0 to 999999999. The handler answers EOVERFLOW for a server's
#   value past its field, as FreeBSD's freebsd11_stat answers an nlink past
#   its old nlink_t (docs/design-programs.md, "Descriptors and files").
# * data_slot's bound is prog_data_slots_max - 1, written out, since a
#   bound here names a limit or a number and no sum of them.
#
# Members (docs/design-abi.md#program-protocol has the full table):
# "version N" is the version every frame carries; "reader c" makes the
# generator emit the C check; "frame NAME to|from TAG [slot] KIND" is a
# frame {TAG, Version, Value} or {TAG, Version, Slot, Value}. An integer is
# u8, u16, u32 or u64, "in MIN MAX" or "values N...", "except N",
# "unique" (no two values of the kind in one frame are equal) and
# "refers LIST" (the value is the first field of an element of LIST that
# holds no refers value itself). A text has "max N", "utf8",
# "refuse nul", "assign" (a name before its first "="), "path" (absolute
# and normalised) and "sum TOTAL"; "total NAME MAX" bounds the texts marked
# "sum NAME", each counting its length and its NUL. A list has "max N" and
# "ascending"; a map's "field" keys must be present and its "optional"
# keys may be; a union's "case ATOM [=ATOM...] [KIND...]" is its atom, or
# a tuple of its atom, its literal atoms and its fields; a "reply KIND"
# line after a request's case names the union of its replies. "boolean",
# "signal" and "errno" are built in: a signal's protocol name from
# abi/signals.txt and an error's from abi/errno.txt, each read as its
# number. "frame NAME to TAG slot reply REQUEST" is the reply frame, whose
# value is the reply the request on its slot takes, REQUEST naming the
# slotted frame from the program. "capability NAME" declares a capability handle:
# a u64 other than cap_null; no two capabilities of a frame are equal.
# A handle is 64 bits, so every other u64 kind or field fails, as does an
# integer excepting cap_null. "offset NAME [in MIN MAX]" declares a file
# offset, FreeBSD's off_t: a signed 64-bit integer, 0 to 2^63 - 1 unless
# the range reaches below 0, which no integer kind spells and whose C
# value is int64_t, never a capability. "time NAME" declares a time_t of
# whole seconds, any signed 64-bit integer, whose C value is
# erx_profile_time_t, neither an offset nor a capability. For a union a frame to the program carries,
# the generator walks each case's capabilities and refuses one nested
# inside another kind.

limit prog_frame_max u32 196608
limit prog_pid_max u32 2147483647
# FreeBSD's OFF_MAX, the largest off_t: an offset kind's bound, and a file's
# offset and size wherever erXos's Erlang holds one (erx_file_remote).
limit off_max u64 0x7fffffffffffffff
limit prog_args_max u32 131072
limit prog_path_max u32 4096
limit prog_fds_max u32 1024
limit prog_data_slots_max u32 16
# Each slot of a program's data area, in bytes: the session sizes the area
# and the program maps it as data_slots of these.
limit prog_data_slot_bytes u32 65536
# The labels of the doorbells bound into a program's group. The channel's
# bell takes prog_channel_label. A pipe end's takes
# (Pipe << pipe_label_shift) | End, computed in 64 bits, which is at least
# 2^32 because Pipe is at least 1, so no pipe end's label is the channel's.
limit prog_channel_label u64 1
limit pipe_label_shift u64 32
# The bytes of a frame the session writes after the startup message, a
# report or a reply: the executor copies each whole into a buffer of this
# size and refuses a longer one. The profile's largest report, {erx_prog,
# 1, {pipe_writer, ...}} with three capabilities as 64-bit integers, takes
# about 120 bytes of ETF, and its largest reply, pipe's {ok, Read, Write}
# with every capability, pipe and end number at its widest, 276.
limit prog_report_max u32 512
# A program's buffer place (docs/design-display.md, "The pixel area"): a
# window's buffer leased to a program is mapped from prog_mem_base, for at
# most prog_mem_bytes, the largest buffer, 16,384 pixels square at 4 bytes
# a pixel. The place's first page number is below 2^32, as the startup
# message needs, and the place lies inside the stopgap's task range, 2^38 to
# 2^39, above the address a program is linked at.
limit prog_mem_base u64 0x7f00000000
limit prog_mem_bytes u64 1073741824

protocol erx_prog
  version 1
  reader c
  integer process_id u32 in 2 @prog_pid_max
  integer parent_id u32 in 1 @prog_pid_max
  integer fd u16 in 0 1023
  integer dup_target u16 in 0 1023 refers fds
  capability cap
  integer open u16 in 0 0xffff
  integer umask u16 in 0 511
  integer data_slots u8 in 1 @prog_data_slots_max
  integer pipe_id u32 in 1 0xffffffff
  integer end_id u32 in 1 0xffffffff
  integer wend u32 in 1 0xffffffff
  integer wend_count u32 in 1 0xffffffff
  integer rix u8 in 0 @pipe_rix_max
  integer lane_size u32 values 16384 65536
  integer mem_page u32 in 1 0xffffffff
  integer mem_pages u32 in 1 0xffffffff
  integer open_flags u32 in 0 0xffffffff
  integer file_mode u16 in 0 4095
  integer data_slot u8 in 0 15
  integer io_count u32 in 1 @prog_data_slot_bytes
  integer io_done u32 in 0 @prog_data_slot_bytes
  offset file_offset
  offset seek_offset in -0x8000000000000000 0x7fffffffffffffff
  integer stat_mode u16 in 0 0xffff
  integer stat_nlink u32 in 0 0xffffffff
  integer stat_id u32 in 0 0xffffffff
  integer time_nsec u32 in 0 999999999
  time file_time
  total args @prog_args_max
  text arg max @prog_args_max utf8 refuse nul sum args
  text env_var max @prog_args_max utf8 refuse nul assign sum args
  text cwd max @prog_path_max utf8 refuse nul path
  text file_path max @prog_path_max refuse nul
  list argv arg max @prog_args_max
  list env env_var max @prog_args_max
  list signals signal max 128 ascending
  union access
    case read
    case write
    case read_write
  union end_state
    case open
    case gone
  tuple pipe_end pipe_id end_id
  tuple reader rix cap
  list write_readers reader max @pipe_readers_max ascending
  list read_readers reader max @pipe_rix_max ascending
  union writer_state
    case open cap
    case gone
  tuple writer wend cap cap lane_size writer_state
  list writers writer max @pipes_quota ascending
  map write_end
    field wend wend
    field ring cap
    field rpage cap
    field size lane_size
    field readers write_readers
  map read_end
    field rix rix
    field lock cap
    field wends wend_count
    field writers writers
    field readers read_readers
  union descriptor
    case pipe =write pipe_end write_end
    case pipe =read pipe_end read_end
    case socketpair pipe_end read_end pipe_end write_end
    case file open access
    case tty open access
    case dir open
    case socket open
    case mem mem_page mem_pages
    case dup dup_target
    case null
  tuple fd_entry fd descriptor
  list fds fd_entry max @prog_fds_max ascending
  tuple data_area cap data_slots
  union image
    case object cap
  map start
    field pid process_id
    field ppid parent_id
    field pgid process_id
    field argv argv
    field env env
    field cwd cwd
    field spawn boolean
    field sigmask signals
    field sigignore signals
    field umask umask
    field data_area data_area
    field fds fds
    optional image image
  # pipe's Flags, and its reply: the program's two new ends, each a
  # descriptor naming values in the program's table (docs/design-pipes.md,
  # "Making a pipe").
  union pipe_flag
    case cloexec
    case nonblock
  list pipe_flags pipe_flag max 2 ascending
  union pipe_reply
    case ok descriptor descriptor
    case error errno
  union kill_reply
    case ok
    case error errno
  union probe_reply
    case ok
    case error errno
  union open_reply
    case ok open
    case error errno
  union io_reply
    case ok io_done
    case error errno
  union whence
    case bof
    case cur
    case eof
  union seek_reply
    case ok file_offset
    case error errno
  # getattr's reply: the attributes the file's server gave, each key present
  # only when it gave that field, so a field it did not give is never sent
  # as a value.
  map stat
    optional mode stat_mode
    optional nlink stat_nlink
    optional uid stat_id
    optional gid stat_id
    optional size file_offset
    optional atime file_time
    optional atime_nsec time_nsec
    optional mtime file_time
    optional mtime_nsec time_nsec
    optional ctime file_time
    optional ctime_nsec time_nsec
  union getattr_reply
    case ok stat
    case error errno
  union clunk_reply
    case ok
    case error errno
  # kill's Signal is a signal's name, never 0: kill(pid, 0), which only
  # checks that kill would reach the target, is the request probe.
  union request
    case pipe pipe_flags
    reply pipe_reply
    case kill process_id signal
    reply kill_reply
    case probe process_id
    reply probe_reply
    # The file requests (docs/design-programs.md, "Descriptors and files"):
    # 9P2000.L's operations, each a case of its own after the atom file, a
    # path in place of a walked fid and the program's open in place of an
    # opened one.
    case file =lopen file_path open_flags
    reply open_reply
    case file =lcreate file_path open_flags file_mode
    reply open_reply
    case file =read open io_count data_slot
    reply io_reply
    case file =write open io_count data_slot
    reply io_reply
    case file =pread open file_offset io_count data_slot
    reply io_reply
    case file =pwrite open file_offset io_count data_slot
    reply io_reply
    case file =getattr open
    reply getattr_reply
    case file =clunk open
    reply clunk_reply
    # An operation the session answers from its own tables: lseek on the
    # open's description (docs/design-programs.md, "The program protocol").
    case local =seek open seek_offset whence
    reply seek_reply
  union notice
    case closed pipe_id end_id
    case drained pipe_id end_id wend
  union report
    case pipe_writer pipe_id end_id wend cap cap lane_size cap end_state
    case pipe_writer_gone pipe_id end_id wend
    case pipe_reader pipe_id end_id rix cap end_state
    case pipe_reader_gone pipe_id end_id rix
    case pipe_lost pipe_id end_id
    case pipe_server_lost
  frame start to erx_start start
  frame request from erx_prog slot request
  frame reply to erx_prog slot reply request
  frame notice from erx_prog notice
  frame report to erx_prog report
