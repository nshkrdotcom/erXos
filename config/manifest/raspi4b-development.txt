# The Raspberry Pi 4 Model B's part of its development manifest on the stopgap
# (config/platforms/raspi4b.json; docs/plan.md, 1b-I). The manifest is the records every
# board takes, config/manifest/development.txt, followed by these (Platform#manifest_source).
# Together they configure the system domain, three configured domains, storage, network and
# display, and the system principal's session template, from which the console starts root's
# session at boot (docs/design-system.md, "Booting"). This part holds the machine, the
# system principal, the apps row, the display domain's limits, the units and windows of
# the board's devices and the network domain's row, whose driver is the board's. The
# common part holds the storage and display domains' rows, the shares, runtime limits and
# the other limits, and the services and facets; QEMU virt's part
# (config/manifest/qemu-virt-development.txt) gives their measurements.
#
# The storage domain, an interpreter service domain, holds the platform record's sd unit,
# EMMC2 and the legacy SD controller that shares its line (docs/design-storage.md, "The SD
# controller's line"). The unit is named block, as on QEMU virt, because storage_ctl acts
# on that unit name. The legacy controller is of no kind a runtime drives, so the domain
# holds it with the unit and is given no record of it and no register window onto it, and
# no driver opens it (docs/design-shared-devices.md, "The unit rule"). erx_blk drives
# EMMC2's sdhci record with its SD device process (erx_blk_sd), which logs that the SD card
# is not driven when no card answers. The domain holds the card's data window and serves
# /data, littlefs on that partition, as the data facet. A boot with no card on EMMC2 has no
# volume, so the storage domain provides no mint for data, the grants stay idle and /data
# answers eio.
#
# The system domain holds four units (docs/design-platforms.md, "Raspberry Pi 4 Model B"),
# of one register page of the board each: the console's, the mini UART's page, which it
# shares with the auxiliary SPI controllers that no driver here drives, and the host
# link's, the PL011s' page, of which the host link uses UART3, both in the common part; and
# rng, the RNG200, which no runtime drives and the root reads itself at boot when /chosen
# carries no seed, at the window its row in the platform record states and only when the
# firmware's tree names that window (docs/design-stopgap.md, "The Raspberry Pi 4", its
# entropy item); and watchdog, the power-management block's watchdog, which no runtime drives
# either and the root's watchdog thread arms and reloads, at the window its row states and only
# when the firmware's tree names that window (docs/design-platforms.md, "The watchdog"). The
# console's driver is erx_mini_uart, which keeps the divisor the firmware set.
#
# The display domain holds the framebuffer's unit and runs the firmware framebuffer's
# driver, erx_firmware_fb, and the window system's screen (docs/design-display.md, "The
# display device"): the root reads the framebuffer the firmware set up, prints its line
# (docs/design-device-tree.md, "The lines") and writes the display domain its record, so a
# screen on HDMI 0 shows the display's windows, the dashboard's on the card, which carries
# the kiosk enabled (the apps row below). A boot whose firmware set up no
# framebuffer, QEMU's raspi4b model without the raspi4b suite's stand-in for the firmware
# among them, gives the domain no framebuffer record, and the domain runs without a
# screen. Its 40 MiB is QEMU virt's 24 MiB, which holds no screen image there, the gpu's
# being device memory, and 8 MiB for the screen image erx_firmware_fb keeps in the domain's
# own memory, one 1920x1080 screen of 32 bits (8,294,400 bytes), with 8 MiB of headroom; a
# larger screen, 4K's 31.6 MiB among them, does not fit, and the driver ignores it. Its
# outer budget is 1 MiB and one pixel area of windows_pixels_default, 8 MiB, with its
# 4 KiB lane, for the apps row's one app, and its quota of one connection is that app's.
# Its memory and the display share's 100 mcpu are measured on neither board (TODO.md).
limits display
  memory 41943040
  outer 9441280
  grant @share.display
  spaces none
  lane 4096
  connections 1
  crash 0
  flags none
  runtime_limits @runtime_limits.display
  peer_held 4096
  peer_held_total 4096
# The system principal holds root's one session, 36 MiB and outer 1 MiB, and 1 MiB for
# the outer budget of a domain that has ended while another still holds a connection to
# it, as QEMU virt's comment explains; the storage domain, 30 MiB and outer 1 MiB; the
# network domain, 36 MiB and outer 1 MiB; and the display domain, 40 MiB and outer 9 MiB
# and 4 KiB: 155 MiB and 4 KiB in all. The system baseline is QEMU virt's 46 MiB.
# root_memory, 275 MiB and 4 KiB, admits the baseline, the principal's 155 MiB and 4 KiB,
# the apps row's 66 MiB, the SD controller's 1 MiB of DMA memory and GENET's 1 MiB of
# device memory with 6 MiB no one is promised, and lies well below what the smallest Pi 4
# the record names leaves the root: RAM less fiasco_reserve is 890 MiB there.
principal system
  memory 162533376
  grant @share.users
  domains 5
  names 64
  default_limits @limits.native
  ceiling_limits @limits.native
# The apps row (docs/design-packaging.md, "The apps row"): 66 MiB, one app of the default
# 64 MiB with its session's outer 1 MiB and the outer budget of one that has ended; max 1,
# the card's one app, the dashboard, so the display domain's outer budget pays for one
# pixel area; and the display and net, which the build grants the app template. The app
# is a principal with a domains quota of one, so max_domains is the system principal's
# five and the one app. max_connections, 15, holds the eleven of the network domain's
# comment and the app's session's four: its system connection, packages, the display and
# net.
apps
  memory 69206016
  max 1
  services display net
machine

  system_principal @principal.system

  holder @domain.display
unit block
  placement "sd"

  holder system
unit watchdog

# data: the card's data partition, whose sectors the medium layout gives (partition 0,
# abi/medium.txt), read-write for the storage domain alone, as on QEMU virt.
# record_volume: the whole record partition, the FAT volume that holds root's
# authorized_keys, read-only for the storage domain, the system window's holder, which
# serves the keys it names as login_keys (docs/design-ssh.md, "Root's login keys on the
# medium"; docs/design-storage.md, "Removable media: FAT").
window record_volume
  holder @domain.storage
  device "/emmc2bus/mmc@7e340000"
  role record_volume
  partition 0
  rights read
  image none
window data
  holder @domain.storage
  device "/emmc2bus/mmc@7e340000"
  role data
  partition 0
  rights read,write
  image none
# system: the booted slot's system partition, read-only for the storage domain, whose
# block driver serves it (docs/design-stopgap.md, "The booted slot"), as on QEMU virt.
window system
  holder @domain.storage
  device "/emmc2bus/mmc@7e340000"
  role system
  partition 0
  rights read
  image none
# The system partition's image and tree, from the release image the packer writes
# (docs/design-stopgap.md, "The booted slot"), handed to the system window's holder.
system_image
  input @artifact.release
# network: QEMU virt's network domain row for row (config/manifest/qemu-virt-development.txt,
# whose comment explains its memory, connections and restarts), an interpreter service
# domain that holds the net unit, the platform record's GENET (docs/design-platforms.md,
# "The Ethernet controller's unit"), and runs the network stack
# (docs/design-network-stack.md, "Who holds the network device") over erx_genet, whose
# interface is genet0, as FreeBSD names genet(4)'s first unit. It serves net, a grant of
# the stack, to the system principal's sessions, since the system domain may hold none
# (docs/design-system.md, property 15), and network_ctl, its driver-control facet, which
# acts on genet0's link, to the system domain alone (property 8).
#
# Its 36 MiB is QEMU virt's measurement of the stack over erx_virtio_net; the stack over
# erx_genet is not measured on the Pi (docs/todo-performance.md).
#
# Its grant is the users share, one CPU of the 2,250 mcpu the system share's reserve
# leaves the configured domains (dom_system_reserve, liberx/system/dom_core.c).
#
# Its quota of two connections holds root's session and one more while a session is
# replaced; its system connection counts against no quota (life_connections,
# liberx/system/dom_life.c). At rest the machine holds six of the 11 these rows take: the system
# connections of root's session and of the storage, network and display domains, and the
# session's data and net; the other five are the three a replacement session makes beside
# its predecessor's closing rows and the two a restarted configured domain makes, as on
# QEMU virt. The apps row's one app takes four more (the apps row's comment).
domain network
  principal @principal.system
  limits @limits.network
  kind service
  flags none
  runtime @artifact.emu
  release @artifact.network
  restarts 5
  restart_period_s 600
  args "-- -root / -bindir /bin -progname erl -home / -nouser -nocookie -no_epmd -proto_dist erx -erx_net interfaces {erx_genet,interfaces,[]} -erx_net runtime erx_net_erxos"
# ntpd, the network time client (docs/design-time.md, "Configuration"): the board has no
# real-time clock, so its wall clock starts at the build's date, and this development
# image is the one exception to the design's decision 1, no default server: it enables
# ntpd with pool.ntp.org, whose first sample the clock service steps to from the
# approximate start. Principal ntpd holds one session of the common part's session
# limits, its memory and its outer budget, on the users share, so root_memory, max_domains
# and max_connections each grow by that session (its net connection). The template's
# release is ntpd's (ReleaseFiles::RELEASE_SCRIPTS), its -eval starts erx_ntpd, and its
# environment sets ERX_START_FLAGS, standing in for the start row's flags until the start
# table carries them (TODO.md, "time, ntpd"). ntpd_net grants the network stack with small
# limits: two sockets (docs/design-time.md, "Who does what"), a lookup's UDP socket and
# the TCP connection inet_res opens beside it for a truncated answer, while an exchange
# holds one socket alone; 128 KiB of buffers, the least a row may state and that
# connection's; and two requests in flight; ntpd_clock grants the clock interface's
# sample operation alone, so ntpd measures and the clock service decides.
principal ntpd
  memory 38797312
  grant @share.users
  domains 1
  names 1
  default_limits @limits.native
  ceiling_limits @limits.native
session ntpd
  limits @limits.session
  runtime @artifact.emu
  release @artifact.ntpd
  args "-- -root / -bindir /bin -progname erl -home / -nouser -nocookie -no_epmd -proto_dist erx -erx_net_client grant {erx_net_client_erxos,grant,[]} -eval {ok,_}=application:ensure_all_started(erx_ntpd,permanent)"
  env "ERX_START_FLAGS=pool.ntp.org"
facet ntpd_net
  name "net"
  grantee @session.ntpd
  service @service.net
  parameter sockets 2
  parameter buffers 131072
  operations none
  max_request 64
  in_flight 2
  reductions 100000
  period_ns 1000000000
  max_heap_size 65536
facet ntpd_clock
  name "clock"
  grantee @session.ntpd
  service @service.clock
  operations sample
  max_request 256
  in_flight 1
  reductions 100000
  period_ns 1000000000
  max_heap_size 8192
start ntpd
  enable YES
